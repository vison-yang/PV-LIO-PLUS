# i-Octree 数值包围盒定向裁决

日期：2026-11-15。只读审查 `upstream/i-Octree/octree2/Octree.h` 和 `i_octree_design.md`；未修改或运行原生实现，未做故障注入。本结论是实施设计审查，不是实现验收。

## 裁决

**原实现阻断；下述方案有条件通过，完成实现和 oracle 前不得解除发布阻断。**

推荐最小可证明方案：每节点增加由实际存储点形成的 AABB，中心/extent 改 double 但仅用于路由、裂分和扩根；搜索及物理删除统一依赖 AABB；删除所有 `inside` 跨节点提前结束；以固定 binary64 运算定义距离，堆、半径平方和剪枝统一使用它。叶端连续点块、八分分派、动态插入/扩根、树上降采样和原地盒删除均保留。不引入历史全点容器，不用重建或线性查询替代树。

这是“最小证明负担”的修法，不是最少改动行数。仅改 double、统一加 epsilon 或对最终距离加一次 nextafter，均不足以通过。

## 1. 盒不变量及维护

对每个非空节点 N，保存六个 **float** 极值 `lo[3], hi[3]`，满足其全部当前后代点逐轴 `lo <= p <= hi`。推荐保存紧极值；空树没有有效盒，不用未初始化值或无限盒代表普通节点。

float 点的 min/max 只选择已有值，不做算术，因此端点本身精确，不需要 outward rounding。转 double 也精确。由此得到根、子节点、扩根节点统一的保守包围证明：叶取极值；父取非空孩子盒的并；扩根新父初始复制旧根盒，插入完成后沿路径求并。证明完全不依赖几何中心是否恰好落在两个 float 中间。

- 初始化/新叶：在原有拷贝或分派时顺带求极值。
- 叶插入/裂分：只对实际接收点维护极值，裂分后父取孩子并。
- 树上降采样拒绝整批：不改变盒或 live count。
- 物理删除：叶压缩时重算幸存点极值；父在递归返回后对至多八个幸存孩子求并；空节点释放。
- 允许删除后暂不缩盒，仍保守，但初版建议重算，避免长期退化，并使测试有唯一紧盒 oracle。
- 不准把 `center +/- extent` 用于搜索、整树收集、盒删除或“包含某点”的正确性判断；这些是路由参数，不再声称它们是保守数据盒。

每节点端点净增加 24 字节；四个几何标量 float→double 再增加 16 字节，实际 `sizeof` 增量由对齐决定。插入每个访问节点增加常数极值合并，删除多至八盒合并；渐近访问复杂度不变。查询最坏仍 O(n)，AABB 可能更紧，也会因移除 `inside` 增加访问，性能收益不可先验承诺。

## 2. 查询度量必须先冻结

建议明确契约为“对存储 float 点与保留为 double 的查询点，按指定 binary64 距离值给出精确检索结果”。不声称任意实数欧氏距离的最后一位精确。

设 RN 为 IEEE-754 binary64 round-to-nearest/ties-to-even；固定如下运算序列，不允许编译器重排、fast-math 或隐式 FMA 改变核：

```
d_i = abs(RN(double(p_i) - q_i))
s_i = RN(d_i * d_i)
D(p,q) = RN(RN(s_0 + s_1) + s_2)
T = RN(r * r)
```

逐点计算、堆排序键、AABB 距离上下界必须使用相同运算序列。查询点不要先转 float，否则查询语义改变，double 窗口/查询与点量化也容易混淆。地图点只量化一次，并明确 snapshot 输出为存储值。

MapManager 的世界点为 double：修改树前完整检查该批输入有限且逐轴在 `[-double(FLT_MAX), double(FLT_MAX)]`，再在 RN 模式转换为 float；转换后的 float 才是地图位置和测试 oracle 的输入。double 原点与量化后点不同是公开契约，不应以原始 double 点作正确性参考。查询保留世界 double，不能为复用 native 原 `float* query` 接口偷偷量化。

合法数值域建议：地图坐标为任意有限 binary32；查询每轴有限且绝对值不超过 `FLT_MAX`；半径为有限 double，`0 < r <= 4*double(FLT_MAX)`，并要求计算出的 `T > 0`。min_extent 另见第 5 节。上述域内所有点距平方和、盒距及 T 都远小于 DBL_MAX。无效查询/radius 返回明确无匹配或参数错误，不能静默截断；无效插入必须修改前拒绝。IEEE subnormal 必须正常工作，禁用 DAZ/FTZ；否则另行收紧输入域并记录，不能声称覆盖所有有限 float。

半径采用严格 `D < T`；kNN 按 D 排序，等距身份不保证。公共拟合范围门槛另用 `D_k <= RN(R*R)`。堆未满时无条件允许插入有限 D；初始化 worst distance 用 double infinity，不能沿用 FLT_MAX 哨兵，否则大坐标点仍被漏掉。

输出距离应保留 double 至公共范围检查和排序结束。若既有公共输出必须 float：只能作为展示/兼容返回值，不能反过来用于精确排名或范围门槛；全 float 坐标域内 squared distance 可能溢出 float，须明确返回策略或收紧该接口域。最佳方案是新后端私有查询携带 double 距离，不修改旧后端语义。

## 3. 不需要 epsilon 的 AABB 剪枝证明

给定 AABB，在各轴取 `near_i = clamp(q_i, double(lo_i), double(hi_i))`。用第 2 节同一个运算核算 L=D(near,q)。远端轴差为 `max(abs(RN(lo_i-q_i)), abs(RN(hi_i-q_i)))`，用同序平方与求和算 U。

对任意盒内 float 点 p，每轴有计算值 `near_diff <= abs(RN(p_i-q_i)) <= far_diff`。理由：浮点 RN 减法对被减数单调；q 在区间外时差同号，取绝对值后仍保序；q 在区间内时最近差为 0，绝对值最大值在两个端点。非负乘法和加法的 RN 运算也单调，故 **L <= D(p,q) <= U**。这是对指定计算度量的界，不是声称 L/U 包住精确实数距离。

因此：

- radius：`L >= T` 可跳过节点；`U < T` 才可整节点收集；其余访问孩子或逐点筛选。
- kNN：堆未满不按 worst distance 剪枝；满后建议 `L > worstD` 才跳过。允许任意等距身份时 `L >= worstD` 也可跳过，但初版用严格大于更便于审计。
- contains：用 `U < T` 替代全部中心/extent 快路径，删除 `3*extent*extent` 门槛。
- overlaps：统一由 L 和当前门槛决定，不保留旧的分支捷径。
- inside：删除所有返回 true 并向祖先传播的提前结束，包括非生产重载，或将未支持重载完全移除。AABB 的兄弟可能重叠；某个 AABB 包含搜索球不证明其它兄弟没有更近点。
- 可以保留按 query Morton 码先访问一个孩子的启发式，但必须检查其余孩子各自的 AABB。不得沿用“优先孩子返回 true 则整个查询结束”。

盒物理删除直接使用 AABB 端点比较：有轴 `hi < box.min || lo > box.max` 则无交；所有轴 `lo >= box.min && hi <= box.max` 则整子树删除；其余递归/叶过滤。闭区间边界统一。端点提升为 double 后与 double window 直接比较，无算术误差；保留六 float 删除盒适配时，窗口到 float 阈值仍按设计文档做有方向的 nextafterf。

## 4. 若要求数学实数距离精确

第 3 节不是这种契约的证明。此时须对距离运算的每个阶段做向外界（差、绝对值、平方、求和以及 r²），不能仅 nextafter 最终总和。剪枝仅在区间证明成立时执行；点距离/半径或两个近邻距离区间重叠时，必须精确二进制有理数比较或经证明的自适应扩展精度回退。固定 long double 并非一般精确 oracle。

这是更大的实现包，本轮不推荐混入。若产品坚持这种“精确”含义，应维持阻断并单列实现，而不是给目前方案错误背书。

## 5. 路由几何、扩根、深层与失败原子性

改 double 的目的为防止 float 扩根/差值溢出并减少退化，不承担查询包围证明。包括 Octant 字段、create/update 局部变量、factor 运算、min_extent、所有临时父/子参数，不能只改结构字段。输入 extrema 先提升 double 再相减。原 float `max-min` 可在转 double 前已经溢出。

初始中心可用 `lo + (hi-lo)/2`，半宽可取最大半跨度及原初始化下限；这只决定路由。零宽/重复点仍形成连续叶，正确性不依赖中心严格位于点范围内部。

扩根保留原“新父包旧根、旧根挂入一个孩子”的机制；新父的数据盒先复制旧根盒。目标批次的路由容纳检查使用 **同时检查 min/max** 的一个循环，避免把前一阶段覆盖当成无需重验的事实。若要保守判断路由立方体包含批次，可用逐轴 `nextafter(abs(RN(endpoint-center)), +inf) <= extent`；多保守一 ULP 只多扩根，不会漏判溢出。该检查仅控制扩根，不用于查询。

有限精度下不要求旧点严格符合新父的 Morton 分割面；插入旧点与新点可能落在数据盒重叠的兄弟，仍由 AABB 搜索得到正确答案。必须在 SOURCE 中如实说明这是保留八叉路由的数据 AABB 修复，不再假定严格不交立方体分区。

需要显式资源/终止条件，建议初版：

- `min_extent` 限定在 `[double(float_denorm_min), double(FLT_MAX)]` 的正有限数；不支持任意接近 DBL_MIN 的参数。
- 预先模拟本批所需扩根，检查所有新 center/extent 有限、extent 正且严格增大；限制扩根次数和总路径深度（例如 512，必须保存/检查现有最大深度，不能只限制新建递归）。
- 超限或数值不前进：本次操作在树修改前明确失败，旧树保持可用；这属于公开操作域限制，不能静默丢点或只插半批。模拟父节点几何不需复制全图。
- 裂分前检查 childExtent 正且小于 extent、几何参数有限、深度预算够用。单纯中心加减不改变数值不必立即失败：可形成单孩子链，但仍受 extent 缩小、min_extent 和深度上限控制。
- 深度预算不足的处理推荐预检拒绝操作，维持作者降采样语义。若改成强制大叶则也能正确检索，但改变分辨率和降采样条件，须另列行为变更，不能混称完全保留。
- 扩根完成提交后再进行分派；任何可能导致参数/深度拒绝的路径须先完成预检。常规内存分配失败的异常安全另由实现 owner 审查，不能把数值预检当完整异常安全证明。

512 不是数学性能保证，也不应未经栈预算验证直接开放。它是可复现的明确拒绝界；工程实现可选更低上限。该方案不宣称任意长对抗更新序列永不触及资源界限。所有已接受操作的包围/查询证明不依赖具体上限。

## 6. 验收及独立 oracle

不运行脆弱版本，只测试修复版及独立参考实现。必须覆盖：

1. 文档反例 `{2^24, 2^24+2}`，query 第一项、radius=1.9：只返回第一项；正负大平移、相邻 float、两轴零宽同样验证。
2. 每次构建、插入、降采样拒绝、裂分、扩根、部分/整盒删除后，独立遍历叶坐标多重集；自底向上重算 min/max，核对节点 AABB 和 live count。不得用中心/extent 判断数据包围。
3. 对每节点抽样查询，独立枚举其点验证 `L <= min(D)`、`U >= max(D)`。覆盖 q 在盒内/端点/边/角、紧贴端点 nextafter(double)、近切半径、重复点和等距。
4. 独立暴力参考按已冻结的计算度量排序/过滤；不能复用生产距离函数作为唯一 oracle。参考用精确有理数或 MPFR 逐步模拟每次 binary64 RN，另与普通 scalar 参考交叉检查。测试标准 real-distance oracle 必须区分预期计算舍入差异与算法漏点。
5. 覆盖 ±FLT_MAX、float subnormal、相反符号、0 与 signed zero、极小正半径导致 T=0 的拒绝、T 刚好邻接距离、非常小/大 min_extent；边界只用确定 bit pattern 和 nextafter，不用十进制猜测相等。
6. double 查询不能表示成 float 的案例，验证没有查询量化；构造两个候选在 float 距离下相等而 double 下可区分，确认内部排名/范围门槛没有提前转回 float。
7. 多方向交替扩根、重复点长链、深度上限的成功/拒绝相邻操作；拒绝前后 snapshot、计数、配置/根状态一致。验证不存在无限循环和超过预算的递归。资源拒绝测试不等同故障注入脆弱版本。
8. 包含/接触/外离的闭盒删除；任意兄弟 AABB 重叠时查询仍完整；整树收集与逐点 radius 参考多重集一致；kNN 少于 k、空/零 k 和所有大距离点仍收齐。

ASan/UBSan、已知所有权和计数修复由主任务组织。编译时记录 IEEE 模式、禁用 fast-math/FMA contraction 的实际 flags，并验证运行时 rounding/FTZ/DAZ 状态；仅源码写 double 不构成证据。测试 seed 与失败坐标持久保存。

具体编译边界建议：将 native 和距离/盒 helper 的实现放入独立 `.cpp`/object target，公共头只暴露声明；对这个目标在全局选项之后显式设置 `-fno-fast-math -fno-associative-math -ffp-contract=off`（GCC/Clang），并关闭该目标 IPO/LTO，防止内联到带 fast-math 的主框架 TU。不能只给某个测试目标加 flags，而实际实例化头文件的 MapManager TU 仍受 `-Ofast`/`-ffast-math` 控制。若继续 header-only，必须约束每个实例化 TU 并检查所有编译命令，隔离 `.cpp` 更易验收。优化 `-O2/-O3` 本身可以保留。

断言 IEEE binary32/binary64 尺寸与 digits，要求 `FLT_EVAL_METHOD == 0` 或用目标平台可验证的标准精度措施；x86-64 通常使用 SSE2，但不能用平台习惯代替检查。运行要求 `fegetround()==FE_TONEAREST`，x86 同时检查 MXCSR DAZ/FTZ 关闭。应在执行入口确认调用线程条件或建立可靠线程初始化约束；不能擅自永久修改共享进程的浮点模式影响旧后端。核查 compile_commands/实际命令与必要的生成代码，确认距离乘加没有 contraction。若工具链不能满足这些要求，需另行证明其实际运算核，当前单调界证明不能自动沿用。

## 7. 主 agent 可下派包

- 高阶实现：AABB 生命周期、double 距离和堆、剪枝替换、inside 清理、double 查询接口、扩根/深度预检与失败原子性；这是耦合核心，不能交机械执行角色决定。
- 边界冻结后机械执行：按上述矩阵生成固定 fixtures、独立 MPFR/有理数参考测试和运行脚本、测 sizeof/节点数/访问节点数、ASan/UBSan 构建、归档日志；oracle 数学设计由高阶 agent 把关。
- 性能包：同一存储点多重集、同一 query 序列下报告耗时/访问节点/内存，不比较不同降采样后的地图来归因数值修复。预计内存上升；访问变化待测，不能声称必然加速。

最终通过条件：代码证明义务全部落地、独立 oracle 及极值/拒绝原子性通过、公共 float 距离边界解决，并确认没有存活的旧中心盒剪枝/inside 路径。当前缺少这些实现证据，故只有设计方向有条件通过。
