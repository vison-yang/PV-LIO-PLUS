# ikd-Tree

论文：[ikd-Tree.pdf](../ikd-Tree.pdf)，arXiv v1（2102.10808v1），*ikd-Tree: An
Incremental K-D Tree for
Robotic
Applications*。作者代码：[hku-mars/ikd-Tree](https://github.com/hku-mars/ikd-Tree)，并作为
FAST-LIO2 的点地图索引。

## 问题与数据结构

静态 k-d tree 每次地图变化都重建代价高；简单动态树则可能因持续插入而失衡。ikd-Tree
为三维机器人地图提供增量插入、点/盒级删除、盒级重插入、在线降采样、kNN
查询和局部重平衡（pp. 1–2）。

节点保存一个点及左右子树、分割轴、树大小、无效点计数、删除标记和包含子树点的轴对齐包围盒。删除使用 lazy
label：先标记而非立即释放节点；子树范围支持盒操作剪枝（p. 2）。

## 更新和查询操作

点级更新递归插入新点并更新子树统计；树违反平衡条件时触发局部重建。盒级更新根据节点包围盒判断与目标盒的相交：不相交即可跳过，完全包含可批量标记/操作，部分相交则继续递归（pp.
2–4）。

在树中降采样时，算法先查找目标体素内已有点和新点，再按体素中心保留代表点并替换该盒内容（p.
3）。重建会展平子树、过滤已删除点并重建平衡树。大子树可在后台线程重建；操作日志记录重建期间新来的插入/删除，随后重放，避免查询期间丢更新（pp.
4–5）。

kNN 查询使用分割面和子树包围范围的距离下界控制回溯，并支持多线程查询（p. 5）。该结构仍然是点索引；本身不定义点面观测或平面协方差。

## 作者实验

随机点实验检验持续插入/盒删除时的更新与查询时间，以及稀疏、紧凑增量分布的影响。室外应用将 FAST-LIO 的静态 k-d tree 替换为 ikd-Tree，使用 Livox Avia 100 Hz 数据，在 i7-8550U / 8 GB 的 DJI Manifold 2-C 上报告扫描融合、近邻查询、增量更新与重平衡耗时，并展示建图结果（pp. 6–8，Table II、Figs. 4–7）。

固定的 arXiv v1 仅有 Table I–II；没有机械式 LiDAR 对比或轨迹/端点误差量化，不能把 FAST-LIO2 论文的实验条件移到这篇数据结构论文中。

## 2026-11-15 对 PV-LIO-PLUS 的范围说明

- ikd-tree 点地图及 PV-LIO-PLUS 的点面适配观测已集成；查询域、输入点集和配套观测均是本地分支的实验条件。
- 主路线可按地图及其对应观测报告；若只比较索引，须另行统一点集、拟平面和权重。
- ikd-tree 的最近邻平方距离与 `nearest_max_range` 比较；配置物理半径时需按 API 正确平方，避免与 iVox 的数值/单位混用。

## 局限

平衡阈值、重建规模和异步日志实现影响延迟与空间开销；lazy delete 会暂时保留失效节点。结构的优势依赖增量变化模式，不能仅凭论文的查询曲线推断 PV
数据回放中的端到端速度。
